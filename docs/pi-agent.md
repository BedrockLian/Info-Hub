## 运行与凭据

私有站的 `MODEL_RUNTIME` 默认 `pi-agent-core`，设为 `direct` 可回退直接传输。模型、地址与凭据沿用现有后端配置；Pi 的凭据回调读取现有 `LLM_API_KEY`，不新增明文凭据文件。每个文章任务创建独立 Agent，不开放工具，不携带其他文章的历史。

Pi 通过自定义传输继续使用本站原生请求格式。所有付费请求仍经过原有回执、次数、金额及谷价安全阀；不使用 SDK 隐式重试。失败、截断和格式不合法的响应不能当作有效结果。

按用户补充，模型在后端 `providers/pi-ai.ts` 中通过 Pi AI 的 `createModels` / `createProvider` 显式注册，Agent 调用 `models.streamSimple`。模型 ID、地址及凭据沿用现有配置，凭据由 provider 在派发时解析；不写入模型定义或另存密钥。当前注册模型为 `deepseek-flash`，文本输入、low/none 场景策略及原生缓存统计由本站适配层保留。

## 批处理与缓存

本站按完整系统提示模板分组排队：每组最多8项，并发2项，待处理上限256。每篇保持独立请求与回执。这是应用内模板批处理，不是服务商离线 Batch API，不承诺批量折扣。现有任务若串行提交，不会因队列自动变成8篇同时调用。

系统提示将稳定指令、简洁约束及 JSON schema 放在文章材料之前；摘要的动态日期不再混入固定前缀。材料原文不做空白归一化。模板哈希按实际发送的系统提示计算。

公共编辑指令固定在 `industry/prompts/pi-editor.md`，版本 `infohub-pi-editor-v1`。所有场景先共享事实准确、自然中文、来源证据、材料视为数据等规则，再附各场景固定指令与输出结构，最后放独立文章材料。评分、时间线和翻译各自保持既有结构，不强制所有任务输出示例的title/summary/translation；回执额外记录 `editorialPolicy`。

有效结果继续复用既有持久回执，身份包含材料、提示版本、模型、生效参数、目标语言和独立评分尝试标记。相同任务恢复可避免再次付费；语言、提示、参数变化和显式重判不会误复用旧结果。迁移0043只增设查找事件表，不重复保存正文或响应。

- 有效结果复用：通过格式校验的任务中，复用次数 / 查找次数；复用无需发起模型请求。
