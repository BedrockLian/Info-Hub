# 缓存优化第一阶段：观测与前缀审计

2026-10-15实现并验收，尚未发布生产。原方案见 [缓存分析与分阶段计划](deepseek-cache-review-20261015.md)。

## 本版行为

- Pi每件任务仍使用独立上下文，模板队列仍每批最多8件、并发2。模型、思考档位、来源、发布权限、金额和次数安全阀保持原设置。
- 根据最终预留并发送的两条文本消息记录固定前缀哈希/字符数、材料哈希/字符数，以及顶层JSON数组记录数。字符单位为UTF-16，不当作模型token。传输继续核对实际消息与预留消息一致。
- 元数据存于现有 `receipts.request.promptAudit`，无需数据库迁移，不存原文、ID列表或密钥。材料哈希标识实际输入内容版本；现有runtimeVersion、模板和参数哈希保留。
- 私有Pi对象输入采用稳定键序；原文字符串、日期、空白和数组顺序保持原样。公共直连序列化不变。审计元数据不加入付费身份，相同有效字符串输入仍可复用旧回执。
- 后台按用途、模型、提示版本、运行方式/版本、档位、模板、实际输入token分档及币种分组。分档为≤2048、2049–8192、8193–32768、>32768及未知。
- 原生缓存仅接受非负安全整数，校验hit不大于输入、hit+miss等于输入（miss缺省时使用已知input-hit）。命中率仅对明细有效的付费尝试加权，单列有效/未知次数和已知命中/未命中量。缺失、非法或矛盾字段保持未知。
- 思考token只使用原生 `completion_tokens_details.reasoning_tokens`，且不大于有效输出总量；缺失时不由文本长度或总输出推算。
- 无效答案的尝试标记失败，费用和用量保留。拒绝携带该响应的attempt编号，旧拒绝不能覆盖新重试。实计与估算费用分别显示，未知结果的美元预留另列，不混合币种。
- 旧回执缺少新字段时展示未记录或未知，不补造历史审计值；新的失败状态修正不倒推历史准确率。

## 离线前缀诊断

```bash
node scripts/audit-prompt-prefix.ts .data/local-requests.json
```

输入是实际wire请求数组，每件的 `messages` 含一条system和一条文本user消息。工具完全离线，只输出索引、哈希、字符数、记录数及相对首件的首次固定前缀差异位置，不输出原文。诊断输入放Git忽略目录，不提交或公开。
