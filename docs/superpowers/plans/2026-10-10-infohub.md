# Info-Hub Personal Intelligence Station Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. User approved execution on 2026-10-10; proceed inline.

**Goal:** Adapt AIHOT into a private personal intelligence station for international affairs, China coverage, technology, games and public affairs.
**Architecture:** Retain the upstream Node API/worker/Web and PostgreSQL publication layer. Extend central read authentication and publication eligibility, customise the industry pack, and disable unrelated jobs.
**Tech Stack:** Node.js >=24.11, TypeScript, Fastify, React Router, PostgreSQL 17, Docker Compose.
**Spec:** ../specs/2026-10-10-infohub-design.md, sections 8–9.

## Global Constraints

- Exactly 24 initial sources: 23 retained and Stratechery; no plaintext keys in Git/images/releases.
- All content exits require a live session or a separate read-only credential.
- Main categories: global_affairs, china_coverage, technology, games, public_affairs.
- Model calls and external messaging remain disabled in development and tests.
- Retain two independent scores and source-tier thresholds until personal samples permit recalibration.
- Disable leaderboard, Codex monitoring, automatic fulltext translation, weekly/monthly model reports.
- Preserve upstream MIT copyright and NOTICE; no AIHOT/MyHOT product branding.
- Only news.blian117.dpdns.org may be deployed; do not modify other server projects.

## Review Focus

- Anonymous navigation and React Router .data requests cannot expose content or cached sessions.
- A read-only token cannot write to admin/ingest endpoints and revoked tokens fail immediately.
- Excluded or unreviewed material cannot leak through direct details, pictures, reports or exports.
- Unsupported model outputs and missing article material must stay pending rather than be silently passed.
- Login return addresses, cookies, alternate ports and shared caches cannot bypass the private boundary.
