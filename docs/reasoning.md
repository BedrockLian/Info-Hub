没有实际 `report_daily` 模型请求；日报只调用 `report_lead`。`monitor.context` 是获取上下文的外部数据请求，不是模型调用。关闭中的模块不因本配置开启。

依据 [DeepSeek 官方思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)（2026-10-11 核查），使用实际支持的 low/high，避免把 medium 误认为单独中档；不使用 max。思考开启时不发送无效的 temperature。低档的总输出额度至少4096 token，高档至少8192；内容理解保留原16384。额度同时容纳思考与答案，不是强制用量，仍可能截断或超时。长度截断一律记录为不可用，保留费用记录，后续重试仍受预算约束。

回执 request 记录实际 `thinking`、`reasoningEffort`、`reasoningPolicy` 和 `maxTokens`；请求身份包含生效参数，因此新参数不会复用旧的关闭思考结果，同参数恢复继续复用。费用预留根据提高后的总输出额度计算，实际结算使用含思考的 completion_tokens。接近预算时可能更早暂停，没有自动扩容或降低强度的回退。

## 先约束提示词，再按实际效果降档

用户进一步明确采用输入提示词约束篇幅，效果不足再降低思考强度。`industry/reasoning.ts` 中的 `inferenceGuidance` 为17个已知目的附加各自的简洁指令，版本 `infohub-concise-v1`；仍仅作用于私有站官方 DeepSeek Flash。原有档位、总输出硬上限、评分规则、金额及次数安全阀不变，不新增自动调档或后台控制界面。

预筛、评分、内容理解的思考篇幅软目标分别为400、1200、1800 token；归组600–800、合并复核1400–1600、综述1000、周报2400、月报3200、公告识别300。关闭思考的场景只约束最终输出的重复与说明文字。翻译明确保留全文，不能为省 token 截成摘要；判断准确性、证据和原任务格式优先于篇幅目标。目标不代表服务商会强制执行或只产生这些 token。

DeepSeek Chat Completions 的 `max_tokens` 是含思考和最终回答的总额度。回执新增 `instructionPolicy`、`softThinkingTokens`，系统提示哈希按实际附加指令后的完整提示计算，费用预留也包含新增指令。相同提示可恢复复用，改变指令不会误用旧结果；截断响应继续拒绝，不为了省费接受残缺判断。

用只读命令 `node --env-file-if-exists=.env scripts/inference-usage.ts --days 7` 比较各场景加指令前后的样本量、输入与输出、延时和费用。服务商未提供思考 token 明细时保持 null，不能拿总输出冒充思考用量。至少积累20个可比较场景样本，结合正文长度、输出格式有效性及人工抽样判断效果；若仍明显超出软目标或没有节省，再将对应场景从 high 调到 low，并复查质量。该观察标准不自动改档、不授权付费测试，也不承诺节省比例。尚无新版实际效果时，不据此下调费用规划。

验证使用隔离空测试库与本地 HTTP 替身，不调用收费服务。覆盖17个实际调用目的的参数、额度、回执、复用身份、预算阻断与截断处理。真实筛选质量、耗时和费用需上线后用自然任务回执及用户标注样本校准，不能以模拟响应宣称准确率提高。
