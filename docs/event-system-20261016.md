# 事件系统修复与组织链路

目标：读者从文章“查看事件全部”进入可读的事件页，了解发生了什么、关键进展、不同来源和原文；AI 在后台组织，阅读不触发收费请求。

## 已核实的问题

2026-10-16 线上版本79523e5：事件详情 loader 直接 fetch API，遗漏私有站请求凭据，将401转换为503。截图事件在统一读取层可正常返回两篇报道、两个进展和综述。线上有475个未合并事件、463个已有综述，因此修复现有系统而非另建平行系统。

现有链路：文章分析通过 → 串行归组 → 同一次发生／同一事件新进展／不同事件判断 → 延迟综述。归组和综述已经经过 chatJson → Pi Agent Core／Pi AI → 付费回执及预算安全阀。缺口是耗尽重试或遗漏入队后没有周期补齐；页面仍把参与数和旧热度当作主信息；综述最新进展通过最近报道猜测链接，缺少明确的证据ID。

## 本次范围与验收

- [x] 修复私有SSR与客户端导航的凭据传递，保留合并308、真实404和取消请求行为；Cookie和只读Bearer均覆盖。
- [x] 后台每五分钟有界补齐近期合格文章的归组及缺失／过期综述；跳过暂停来源的新处理、人工独立决策和已有待执行任务。每轮最多20篇归组、8个综述，综述候选每轮40个、游标轮转，避免未变的旧期次占满扫描窗口。历史文章在SQL限量前排除。
- [x] 综述按固定跨领域编辑提示处理稳定排序的至多40篇材料，保留事件起点和最近39篇；明确引用ID，拒绝越界、重复和未引用的最新进展。同事件并发互斥，输入未变跳过，保存时重验版本和证据。
- [x] 事件页突出概览、关键进展、报道时间线和证据来源，显示整理状态，独立来源按机构去重，清理旧热度主导设计。旧综述兼容，不批量重写历史；旧版没有最新进展引用ID时显示文本，不猜测报道链接。
- [x] 文章“事件脉络”采用完整事件的同一读取条件，不再只查含精选的进展；单来源、暂时没有后续或读取失败时也保留完整事件入口。旧的可读提及报道、未摘要报道继续展示，但不擅自作为AI综述材料。
- [x] 覆盖访问、补齐、AI失败、引用校验、并发、重复付费、过期结果、撤稿及来源暂停；类型检查、隔离Linux后端与网页测试、构建、私有访问烟测及桌面／手机检查。

## 有界重试与费用

原有Pi模板队列、思考档位、金额／次数／谷价阀均不变。归组任务携带文章输入版本，补齐综述记录材料哈希；生成时读取当前材料，保存前再次检查。原任务仍有有限重试，失败耗尽后同一输入不由扫描器无限重开；材料变化或后台人工重试可再次进入。未知付费结果保留，等待既有回执恢复流程。扫描和读者访问不直接发起模型请求。

系统指令和JSON结构位于固定前缀，动态ID、摘要、来源、报道时间放在后部，摘要每篇最多360字符；不追加当前时钟或上一版综述。沿用现有模板批处理及独立Agent上下文。真实DeepSeek原生缓存计数与有效回执复用统计口径保持不变；本次测试不能证明生产缓存命中率提升。
